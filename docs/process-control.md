# Запуск, остановка и сложные команды

В 0.5.0 добавлена отдельная политика автоматического перезапуска после ошибочного
выхода. Она сохраняется в профиле и действует для запусков из панели; по умолчанию
выключена. [Логи, ресурсы и автоперезапуск](diagnostics.ru.md).

В версии 0.3.0 в карточке бота доступны «Запустить», «Остановить» и «Перезапустить».
Существующую библиотеку в окружении бота нужно обновить и один раз запустить бота
обычным способом: SDK запишет идентичность процесса и исходные аргументы Python.
Ботам без этих сведений приложение не отправляет опасные сигналы по одному PID.

## Что сохраняется

- Полный путь Python и исходные аргументы, включая `-m`, `-u`, флаги и значения.
- Настоящая рабочая папка процесса, которая может отличаться от папки main.py.
- PID, время создания процесса, исполняемый файл и UUID сессии.
- Профиль, который владелец может изменить в «Настроить запуск».

Автоопределение видит команду самого Python. Предшествующую активацию окружения,
миграции, PowerShell-оболочку, `uv run` или `poetry run` нельзя достоверно восстановить
изнутри Python. Для них задаётся явный профиль, который повторяется при каждом запуске.
Для venv обычно достаточно полного пути его Python; отдельная активация не нужна.

## Профиль сложного запуска

Пример Linux; на Windows укажите собственные абсолютные пути:

```json
{
  "command": ["/usr/bin/python3", "-u", "-m", "shop_bot", "--config", "config/prod config.json", "--workers", "4"],
  "cwd": "/srv/bots/shop",
  "pre_start": [
    ["/usr/bin/python3", "prepare.py", "--config", "config/prod config.json"]
  ],
  "env_file": "/srv/bots/shop/.env",
  "environment": {"BOT_MODE": "production"},
  "required_env": ["BOT_TOKEN"]
}
```

Команды передаются как массивы аргументов, с `shell=False`. Пробелы, `&`, `;`
и `$()` внутри отдельного аргумента остаются его содержимым. Строка с `&&`
не разбирается скрыто: шаги подготовки задаются отдельными командами.
Если нужен настоящий PowerShell- или shell-скрипт, запускайте его явно, например:

```json
["pwsh", "-NoProfile", "-NonInteractive", "-File", "C:\\Bots\\launch-workflow.ps1", "-Config", "C:\\Bots\\prod config.json"]
```

Можно так же указать `uv` или `poetry`, если они установлены на сервере и доступны
по полному пути или PATH. Именно PowerShell, обычный файл и `python -m` проверены
интеграционными тестами этой версии; запуск через uv/poetry отдельно не проверялся.

Подготовка выполняется последовательно до старта бота. Ошибка шага не запускает
следующие шаги и самого бота; в окне видны номер шага и код завершения.
На один шаг отводится 30 секунд. Можно отменить подготовку кнопкой «Остановить».

## Секреты и окружение

Список обязательных переменных и путь env-файла изначально пусты. Бот может сам
читать свой `.env`: библиотека не добавляет требование `BOT_TOKEN` автоматически.
Имена для дополнительной проверки задаются владельцем вручную. Ранее сохранённые
явные требования сохраняются до их редактирования.

В профиле сохраняются путь env-файла, имена обязательных переменных и несекретные
значения. Токены и пароли в профиле запрещены. Для секрета используйте env-файл
или ссылку `${BOT_TOKEN}` на переменную окружения процесса приложения/SSH.
Содержимое env-файла не возвращается в renderer и не копируется в базу.

Поддерживается простой формат `KEY=value`, необязательные `export`, внешние кавычки,
пустые строки и отдельные строки-комментарии. Код shell, интерполяция и команды
из env-файла не выполняются. Путь может быть относительным к рабочей папке бота.

Если бот сам читает конфигурацию, обязательные переменные профиля задаются владельцем
с учётом этого: preflight проверяет окружение **до** запуска Python. При нехватке
обязательной переменной перезапуск не останавливает уже работающего бота.

## Как останавливается процесс

Сначала bridge записывает адресованную конкретной SDK-сессии команду в SQLite.
SDK проверяет её независимо от пользовательских сообщений и вызывает публичный
`Dispatcher.stop_polling()`. Для webhook или собственного event loop передайте
`shutdown=...` в `start()` — функцию остановки приложения или async callback.

```python
stopped = asyncio.Event()
monitor = start(bot=bot, dispatcher=dp, shutdown=stopped.set)
```

Если за 6 секунд процесс не завершился, окно предлагает отдельное принудительное
действие. Оно проверяет PID **и время создания**, владельца и исполняемый файл,
а затем завершает подтверждённый процесс и его дочерние процессы. PID сам по себе
недостаточен. Сам bridge и его родительские процессы защищены от остановки.
Перезапуск не создаёт новый процесс, пока старый не завершён.

Одновременные команды из нескольких окон сериализуются через SQLite; второй старт
работающего бота отклоняется. Бот продолжает работать после закрытия приложения
или SSH-сессии: за ним остаётся дочерний launcher, который ждёт завершения и
записывает его код. Это не сетевой сервис, слушающих портов нет.

## Границы

- Раздельно остановить двух ботов, работающих в одном OS-процессе, нельзя: такая
  операция отклоняется. Для независимого управления запускайте их разными процессами.
- Управление Windows-службой, systemd unit или внешним supervisor пока не добавлено.
  Если сторонняя служба сама перезапускает бота, она продолжит делать это.
- При полном перезапуске компьютера автозапуск ботов настраивается отдельно.
- stdout/stderr запускаемой команды не записываются в журнал приложения; для
  ошибки до подключения SDK видны статус запуска и код завершения.
- Профили и история запусков находятся в `process-control.sqlite3`, а данные
  событий — в файлах ботов. Скрипт резервирования сохраняет оба вида баз.
- Новая схема SDK версии 2 создаётся автоматически при обновлении конкретного бота.

Пример с вложенными роутерами, FSM, обработкой ошибки, подготовкой и фоновой
дочерней программой находится в [examples/complex_bot](../examples/complex_bot/main.py).
Его офлайн-сессия запрещает сеть, но использует настоящий aiogram.
