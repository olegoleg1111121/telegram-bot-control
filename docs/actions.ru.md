# События и аналитика

[Русский](actions.ru.md) · [English](actions.en.md) · [Готовый промпт для ИИ](ai-integration.ru.md)

Начиная с 0.6.0 панель показывает события из кода, вызовы функций и нажатия
inline-кнопок. Откройте **События и действия**, выберите бота, период, источник
и результат. Нажатие на название события фильтрует график и историю.
В истории есть точное время с секундами, результат, длительность и подробности ошибок.
Часовой пояс задаётся в настройках; раскрытая строка также показывает время UTC.

## Подключение

В существующем aiogram 3 приложении после создания Bot/Dispatcher:

```python
from telegram_bot_control import start

monitor = start(
    bot=bot, dispatcher=dp, data_dir="/srv/bot-control/data",
    actions={"catalog:open": "catalog.open"},
)
dp.update.outer_middleware(monitor.middleware())
```

Существующий вызов polling или lifecycle webhook сохраняется. На Windows можно
использовать `data_dir=r"C:\BotControl\data"`. У всех ботов и панели одна папка данных.
SDK не открывает порт. Для подключения с помощью ИИ есть [отдельное задание](ai-integration.ru.md).

## Явное событие

```python
# После успешного завершения реальной операции:
monitor.track_action("order.completed", user_id=customer_telegram_id)

# Опционально: длительность и результат внешней операции.
monitor.track_action("payment.process", outcome="error", duration_ms=150)
```

Метод синхронный, работает и из потоков. Возвращает `True`, если событие принято
в ограниченную очередь; это не подтверждение записи на диск. При переполнении
или закрытом monitor возвращает `False`; число пропусков видно в диагностике.
До SDK startup события остаются в памяти. Для гарантированного завершения
записи при штатной остановке нужен shutdown lifecycle; это телеметрия, а не журнал платежей.

Внутри middleware `user_id` наследуется от текущего Telegram update. В фоновом
коде передайте ID явно, если нужен подсчёт пользователей. События без пользователя
учитываются в общем числе, но не в числе пользователей. В базе ID заменён HMAC
с отдельным ключом каждого бота: пользователи между ботами **суммируются**.

Опциональный `event_id="opaque-operation-key"` позволяет не учитывать повтор
одной операции: сочетание имени и ключа уникально внутри одного бота за сохранённую
историю. Ключ хранится как HMAC. Не используйте постоянный ключ для всех нажатий.
После удаления записи по сроку хранения тот же ключ можно учесть снова.

## Декоратор функции

```python
@monitor.action("report.generate")
async def generate_report(user_id: int):
    return await existing_report_service(user_id)
```

Работает с обычными `def` и `async def`, сохраняет аргументы, результат и метаданные
функции, измеряет длительность и записывает `success`, `error` или `cancelled`.
Исключение не поглощается. Для генераторов и async-генераторов декоратор не подходит.
Аргументы и возвращаемое значение не записываются. Синхронный декоратор должен
стоять непосредственно над функцией, а регистрация aiogram — выше него:

```python
@router.callback_query(F.data == "catalog:open")
@monitor.action("catalog.open")
async def show_catalog(callback):
    await callback.answer()
```

Не нужно одновременно оборачивать и вручную считать один вызов под тем же именем:
это две явные записи. Автоматическое нажатие callback и одноимённое явное событие
того же update в аналитике действий объединяются; счётчик входящих updates остаётся отдельным.
Кнопки без безопасного mapping отображаются как `callback`, их сырые данные не сохраняются.

## Имена, графики и хранение

- Статичные имена из 1–80 латинских букв, цифр, `_`, `.` и `-`. Например, `menu.catalog`,
  `payment.confirmed`, `report.generate`. Не создавайте имя для каждого пользователя/заказа.
- `outcome`: `success`, `error`, `cancelled`. `duration_ms` — конечное неотрицательное число.
- `event_id`: необязательный непрозрачный ключ из 1–80 безопасных символов; не токен/телефон.
- График считает начала срабатываний. Интервалы без событий показаны нулями;
  для длинных периодов шаг автоматически укрупняется до ограниченного числа точек.
- История выдаётся по 50 строк; просмотр ограничен первыми 10 050 совпадениями.
  Для более старых записей сузьте период. Итоги и график учитывают весь выбранный период.
- События хранятся по настройке **Статистика, дней**. Существующие базы старого SDK
  продолжают читаться. Новые явные события требуют SDK 0.6.0 в Python самого бота.
- Ошибки декоратора доступны в истории действий; ошибка, дошедшая до middleware,
  также видна в разделе ошибок входящих обновлений. Общие счётчики не складывают их дважды.

Не передавайте в имена событий тексты сообщений, токены и персональные данные.
В traceback маскируются известный токен бота и распознаваемые секретные параметры;
не включайте произвольные личные данные в сообщения исключений.
