# Архитектура

Актуальное решение — [SQLite-mailbox и stdin/stdout](transport.md).
Оно заменяет HTTP-агент из начального промпта по последнему уточнению владельца.

| Компонент | Реализация |
| --- | --- |
| Подключение | `start(bot=bot, dispatcher=dp)`; определение главного файла |
| События | Отдельное outer middleware aiogram, нормализация кнопок |
| Запись | Ограниченная очередь в боте → asyncio.to_thread → SQLite WAL |
| Идентичность | Telegram ID для бота, UUID для отдельной сессии запуска |
| Состояние | Lifecycle aiogram, heartbeat, штатная остановка и потеря связи |
| Хранилище | Один файл на бота, локальный диск и права владельца |
| Чтение | Python bridge, JSON lines по stdin/stdout, без слушающего сокета |
| Удалённый доступ | Тот же bridge через SSH stdio, без проброса порта |
| Приложение | Electron, React, TypeScript; локальные файлы интерфейса |
| Настройки | Атомарный settings.json сервера и локальные настройки приложения |
| Управление | Профиль запуска, подготовка, штатная остановка SDK и отдельное принудительное завершение |

Схема базы версии 2 создаётся/обновляется при записи; более новые неизвестные версии
не перезаписываются. События вставляются идемпотентно по Telegram update ID внутри
файла конкретного бота. Пользователи псевдонимизируются HMAC; уникальные за любой
диапазон считаются COUNT(DISTINCT), дневные уникальные не складываются.

Команды остановки адресованы UUID сессии через SQLite. Идентичность процесса
проверяется по PID, времени создания, исполняемому файлу и владельцу.
Запуск выполняет конечный launcher с `shell=False`; профиль и статусы сохраняются
в `process-control.sqlite3`. Закрытие bridge не останавливает управляемого бота.
Подробности: [управление процессами](process-control.md).

Безопасность окна: contextIsolation и sandbox включены, nodeIntegration выключен,
renderer получает только конкретные методы preload. Нет внешних ресурсов и сетевых
запросов из renderer. SSH-ключи используются процессом SSH, а не страницей интерфейса.

Детали настройки и запуска — [README](../README.md), история требований —
[требования](specification.md), фактические проверки — [validation](validation.md).
