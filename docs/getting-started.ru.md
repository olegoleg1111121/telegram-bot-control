# Первый запуск и подключение ботов

Можно работать с **обычным Python без venv** или уже существующим окружением.
Устанавливайте SDK через тот же интерпретатор, которым запускаете бота.
[Готовый промпт для интеграции с помощью ИИ](ai-integration.ru.md) · [События и графики](actions.ru.md).

```sh
python -m pip install --upgrade telegram-bot-control
tgbots open
```

## Как открыть приложение на Windows

Установленная версия открывается ярлыком **Telegram Bot Control** на рабочем столе
или через меню «Пуск». Установщик 0.6.0 создаёт оба ярлыка, в том числе при обновлении.

Portable-версия открывается файлом `Telegram Bot Control.exe` из распакованной папки.
Сохраните рядом все DLL, `resources`, `locales` и файлы лицензий. Один exe переносить
нельзя. Запуск portable сам по себе ярлык не создаёт. В исходном проекте можно вызвать:

```powershell
.\scripts\create_desktop_shortcut.ps1
```

Сценарий создаёт ярлык текущей сборки из `release/desktop-build/win-unpacked`.
Если переместить эту папку, ярлык нужно создать заново.

Для запуска из исходников откройте PowerShell **в корне проекта**:

```powershell
.\.venv\Scripts\tgbots.exe open --data-dir "C:\BotControl\data"
```

Команда открывает локальное подключение именно к указанной папке, даже если раньше
было сохранено другое подключение. В собранной версии задайте путь к exe перед командой:

Если панель уже работает в трее, измените папку через её настройки или сначала
выберите «Выйти из приложения». Повторный запуск возвращает существующее окно.

```powershell
$env:BOTCONTROL_DESKTOP = (Resolve-Path '.\release\desktop-build\win-unpacked\Telegram Bot Control.exe').Path
.\.venv\Scripts\tgbots.exe open --data-dir "C:\BotControl\data"
```

Python устанавливается отдельно. Для разработки также нужны Node.js 24, pnpm 11.25.0
и выполненная сборка `pnpm --dir desktop run build`. Для установленного exe Node.js
и pnpm не нужны.

## Обучение при первом запуске

При первом открытии автоматически появляется мастер из пяти шагов:

1. Знакомство с возможностями и выбор русского или английского языка.
2. Локальное подключение или SSH: Python, папка данных и настоящая проверка соединения.
3. Команда установки пакета через pip и фрагмент кода для существующего aiogram-бота с копированием.
4. Проверка появления бота после его первого обычного запуска.
5. Управление процессами, трей и настройки истории.

Можно выбрать «Пройти позже» или закрыть мастер. Это сохраняется: он не мешает
каждому следующему запуску. Повторно откройте **«Обучение и подключение»** в боковом
меню или меню трея. История ботов при этом не изменяется.

## Подключение Python и общей папки

На своём компьютере выберите **Настройки → Подключение → Локально**.
Укажите полный путь к `python.exe`, например `C:\BotControl\.venv\Scripts\python.exe`,
и папку данных `C:\BotControl\data`. Нажмите **«Подключиться»**.

В выбранном Python должен быть установлен наш пакет. Установите его из PyPI:

```powershell
& "C:\BotControl\.venv\Scripts\python.exe" -m pip install telegram-bot-control
```

У ботов могут быть разные виртуальные окружения. Устанавливайте библиотеку в каждое
из них. Python панели читает общие данные, а Python каждого бота запускает самого бота.
Не копируйте для этого чужие venv и не меняйте рабочий интерпретатор бота.

В окружении бота можно установить `"telegram-bot-control[aiogram]"`, чтобы добавить
также aiogram. Для установки без PyPI доступен wheel в GitHub Release.

## Как добавить aiogram-бота

Нажмите **«Подключить бота»** слева: если соединение с данными уже работает,
откроется сразу шаг интеграции. Проверка Python сама по себе не изменяет код бота.
Если бот был подключён раньше, используйте **«Бот уже подключён? Проверить папку»**
на пустом экране и укажите прежнюю папку данных. Текущий путь показан рядом.

В существующем основном файле найдите создание `bot` и `dp`. Внутри вашей асинхронной
`main()`, до `await dp.start_polling(bot)`, вставьте:

```python
from telegram_bot_control import start

# Внутри main(), когда bot и dp уже созданы:
monitor = start(
    bot=bot,
    dispatcher=dp,
    data_dir=r"C:\BotControl\data",
)
dp.update.outer_middleware(monitor.middleware())

# Существующий запуск оставьте на месте:
await dp.start_polling(bot)
```

Это фрагмент для вставки в существующую функцию: не создавайте второй `Bot`, второй
`Dispatcher` или второй вызов `start_polling()`. Роутеры и обработчики сохраняются.
Укажите **одну и ту же абсолютную папку данных у ботов и в панели**.

Сохраните файл и один раз запустите бота обычной командой, например:

```powershell
& "C:\Bots\shop\.venv\Scripts\python.exe" "C:\Bots\shop\main.py"
```

Бот появится автоматически после startup aiogram. Отдельно вводить токен в панель
или нажимать «Добавить по токену» не нужно. Одна только строка импорта не подключает
сбор. Произвольные файлы серверной папки не сканируются.

## Как пользоваться

Для нового проекта теперь можно нажать **«Подключить бота»** и пройти
[мастер подключения](project-wizard.ru.md): папка, Python и главный файл,
код интеграции, ID и команда запуска. Он добавит запись в список без запуска кода.

В карточке доступны **Ресурсы процесса** (CPU/RSS/потоки) и **Логи** существующего
logging/Loguru. Автоперезапуск включается отдельно в настройках запуска бота.
[Подробная инструкция](diagnostics.ru.md).

Выберите бота слева. В карточке находятся **«Запустить», «Остановить», «Перезапустить»**,
его активность, команды, нажатия и сведения о процессе. В разделе «Ошибки» похожие
исключения объединены; строка раскрывает технические подробности.

Обычный запуск Python определяется при первом старте библиотеки. Если используются
PowerShell, подготовка, дополнительные аргументы или env-файл, откройте **«Настроить
запуск»** и сохраните профиль. Примеры: [управление процессами](process-control.md).

Если для запуска нужен токен из переменной окружения, укажите env-файл в профиле
или загрузку конфигурации самим ботом: окружение первоначального терминала не
сохраняется автоматически. Не вставляйте токены в командную строку профиля.

Крестик **прячет окно в трей**. Значок может находиться под стрелкой `^` возле часов
Windows. Нажатие на значок, пункт «Открыть» или повторный запуск возвращает то же
окно. Полный выход: правой кнопкой по значку → **«Выйти из приложения»**.
Боты продолжают работать и после полного выхода из панели. Кнопка сворачивания
работает обычным способом — через панель задач.

Если системный трей недоступен, крестик завершает панель. На Linux наличие трея
зависит от графического окружения. Автозапуск ботов после перезагрузки сервера
настраивается отдельно.

## Linux-сервер

На сервере установите пакет в окружения ботов и Python для чтения данных. В панели
выберите **Linux по SSH**, укажите адрес, пользователя, порт, полный путь серверного
Python и общую серверную папку, например `/srv/bot-control/data`.
Тот же путь задайте ботам в `data_dir`.

Сначала подтвердите ключ сервера обычным `ssh owner@server`. Для зашифрованного
клиентского ключа используйте `ssh-agent`. На сервере без рабочего стола приложение
не запускается: там работают боты и библиотека, а окно открывается на вашем компьютере.

## Если ничего не появилось

- Проверьте, что библиотека установлена именно в Python, которым запускается бот.
- Проверьте вызов `start()`, подключение middleware и успешный startup бота.
- Сравните абсолютные папки данных в коде бота и настройках панели.
- Убедитесь, что не запущен второй polling-процесс того же Telegram-бота.
- Ошибка до старта библиотеки видна в терминале самого бота; история до подключения
  библиотеки не загружается.

Для знакомства без Telegram-токена запустите в одном терминале:

```powershell
.\.venv\Scripts\tgbots.exe demo --bots 3 --data-dir .bot-control\demo
```

В другом терминале из той же папки:

```powershell
.\.venv\Scripts\tgbots.exe open --data-dir .bot-control\demo
```

Это отдельная демонстрационная папка с синтетическими событиями. `Ctrl+C` останавливает
демо. Реальные боты и их данные не затрагиваются.
