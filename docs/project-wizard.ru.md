# Мастер подключения существующего проекта

В подключённой панели нажмите **«Подключить бота»**. Если соединение с Python не
настроено, сначала откроется проверка подключения. Мастер работает с путями на
подключённом сервере — локальном, SSH или сервере веб-панели.

1. Укажите полный путь к папке проекта. Мастер найдёт типичные main.py, bot.py,
   app.py, __main__.py, src/main.py и Python из .venv/venv/env. Свой главный файл
   и интерпретатор можно указать вручную. Модули бота не импортируются и не запускаются.
2. Установите wheel из релиза в окружение бота. Мастер покажет код `start` и
   middleware с общей папкой данных и, когда возможно, именами ваших Bot/Dispatcher.
   Поместите код после их создания, перед запуском polling/webhook. Если импорт
   уже найден, обновите имеющееся подключение. Мастер ничего не переписывает.
   Для фабрик и нестандартной структуры проверьте имена переменных вручную.
3. Укажите числовой Telegram ID бота, название и проверьте команду. ID — цифры до
   двоеточия в токене; сам токен панели не нужен. Для запуска модулем используйте
   массив `["/полный/путь/python", "-m", "my_bot", "--config", "settings.json"]`.
   Подготовительные команды задаются массивом массивов аргументов.

Поле env-файла изначально пустое. Если бот загружает свой .env сам, оставьте его
пустым. Мастер видит только наличие .env, содержимое не читает. После сохранения
бот сразу появится в списке с состоянием «Ожидает запуска». Когда код подключён,
нажмите **«Запустить»**: настоящий aiogram-процесс зарегистрирует сессию и обновит
имя, username и состояние. Одно сохранение проекта процесс не запускает.

Подключение существующего logging/Loguru, графики и политика перезапуска описаны
в [инструкции диагностики](diagnostics.ru.md). Для webhook-приложения сохраняются
требования вызвать lifecycle dispatcher и задать cooperative shutdown из SDK.
